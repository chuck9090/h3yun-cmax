# H3Yun CMax - 氚云代码同步工具

一个 VSCode 插件,用于自动从氚云低代码平台同步应用代码到本地,实现版本管理、代码智能提示和 AI 辅助开发。

## 重大更新说明

从本版本开始,插件调整了本地项目目录和 Git 管理方式,以支持在同一个工作区中管理多个氚云应用。

- 工作区下会自动创建 `氚云代码` 目录,新构建的应用统一创建在该目录下。
- `.h3token` 统一保存在 `氚云代码/.h3token`,不再保存在应用目录下。
- `.gitignore` 和 Git 仓库统一放在 `氚云代码` 目录下,多个应用共用一个 Git 仓库。
- `cmax.json` 统一保存在 `氚云代码/cmax.json`,集中记录所有应用和表单结构信息,应用目录下不再保存该文件。
- 同步应用时,Git 只会检查和提交当前应用目录的代码变更;根 `cmax.json` 的任何变更都不会触发提交询问,也不会提交其他应用目录的代码。
- 旧版目录结构不会自动迁移。已有旧项目请重新执行一次“从氚云构建项目”,使用新方案生成应用目录。

如果在旧应用目录上执行“从氚云同步”,或“氚云代码”目录下缺少 `.h3token`,插件会提示可能仍在使用旧方案,并提供更新指南。请按照指南重新构建一次项目。

## 功能特性

- **自动构建项目**: 输入应用编码、企业引擎编码 enginecode 和 Token,自动下载应用下所有表单的字段表、表单代码和列表代码
- **智能文件夹管理**: 应用和表单文件夹使用编码生成稳定后缀,应用以 `a` 开头、表单以 `f` 开头,默认由对应编码的 MD5 前 6 位组成;发生冲突时自动增加哈希长度
- **增量同步**: 支持右键点击“氚云代码”目录下的应用文件夹进行增量同步,存在当前应用代码变更时可自动提交 Git 变更
- **Token 管理**: Token 统一保存到“氚云代码”目录下的 `.h3token`,并自动通过该目录的 `.gitignore` 忽略;Token 缺失或失效时会提示重新输入
- **更新 Token**: 只需输入一次 Token,即可更新“氚云代码”目录下供所有应用共用的统一 `.h3token`
- **配置持久化**: 在“氚云代码”目录自动生成统一 `cmax.json`,集中记录所有应用和表单结构信息
- **接口版本切换**: 支持在 `cmax.json` 中配置使用氚云老版本接口或新版本接口
- **失败节点报告**: 节点表单结构请求失败时,自动在“氚云代码”根目录生成 `failed-nodes(应用名称).md`,并由 `failed-nodes*.md` 忽略;报表等非表单节点会自动跳过且不会生成报告
- **进度显示**: 实时显示同步进度和状态
- **氚云 API 智能提示**: 在同步生成的前后端代码文件中按 API 层级提供补全与悬浮说明，不会向项目写入 `.d.ts` 或其他声明文件

### API 智能提示

智能提示只在以下同步生成的代码文件中生效：

- `form-frontend.js`：表单前端 API。支持 `$.`、`$.SmartForm.`、`$.SmartForm.ResponseContext.`、`this.` 以及表单控件实例后的分层提示。
- `list-frontend.js`：列表前端 API。支持 `$.` 与 `$.ListView.` 的分层提示。
- `form-backend.cs`、`list-backend.cs`：后端 API。支持 `H3.` 命名空间、`new H3...` 公开构造方法、枚举值，以及 `this.Engine.` 和已声明对象实例的分层提示。

补全项会提供参数占位模板和开发文档说明。提示定义内置于扩展，不会修改同步项目中的业务代码或新增声明文件。

## 安装

在项目根目录找到 `h3yun-cmax-*.vsix` 安装包,然后按以下步骤安装:

1. 在 VSCode 中,点击左侧活动栏的扩展图标(或按 `Ctrl+Shift+X`)
2. 点击扩展面板右上角的 **"..."** 菜单
3. 选择 **"从 VSIX 安装..."**
4. 选择对应版本的 `h3yun-cmax-*.vsix` 文件
5. 等待安装完成
6. **重启 VSCode**(重要!)

安装完成并重启后,可以通过命令面板验证插件是否可用:

1. 按 `Ctrl+Shift+P` 打开命令面板
2. 输入 "氚云" 或 "从氚云构建项目"
3. 能看到对应命令即表示插件已安装成功

## 首次使用:准备认证信息

在使用插件前,您需要准备企业引擎编码 enginecode 和浏览器中的氚云认证 Token。

### 获取 enginecode

1. 使用系统管理员账号登录氚云平台
2. 点击头像进入 **系统管理**
3. 进入 **系统集成**
4. 复制企业引擎编码,即本插件表单中的 `enginecode`

### 获取 h3_token

#### 步骤一:登录氚云

1. 打开浏览器(推荐使用 Chrome 或 Edge)
2. 访问氚云平台并登录您的账号

#### 步骤二:打开开发者工具

1. 按 `F12` 键打开开发者工具
2. 或者右键点击页面任意位置,选择"检查"

#### 步骤三:查找 h3_token

**Chrome/Edge 浏览器:**
1. 切换到 **Application**(应用程序) 标签
2. 在左侧菜单展开 **Storage**(存储) → **Cookies**
3. 点击氚云平台的域名
4. 在右侧列表中找到 **h3_token**
5. 复制其 **Value**(值) 列的内容

**Firefox 浏览器:**
1. 切换到 **Storage**(存储) 标签
2. 展开 **Cookies**
3. 点击氚云平台的域名
4. 找到 **h3_token** 并复制其值

#### 步骤四:保存 Token

将复制的 Token 妥善保存,首次构建项目时需要输入。

**注意**: Token 有一定有效期,如果后续同步时提示 Token 失效,请重复上述步骤获取新的 Token。

## 使用方法

### 首次构建项目(命令面板)

1. 按 `Ctrl+Shift+P` 打开命令面板
2. 输入 "从氚云构建项目" 或 "氚云"
3. 选择对应命令
4. **在弹出的表单窗口中**:
   - 输入氚云应用编码
   - 输入企业引擎编码 enginecode
   - 点击"📖 如何获取 h3_token?"查看详细指南
   - 输入从浏览器获取的 h3_token
   - 点击"开始构建"
5. 插件会自动验证 Token 有效性
6. 验证通过后开始同步,等待完成
7. 构建完成后,插件会询问是否提交“添加 xxx 应用”的构建文件;如果尚未初始化 Git,工具会在后台自动完成初始化,不单独弹窗提示初始化。

普通工作区或缺少根 `cmax.json`、`.h3token` 任一文件时,构建表单需要填写应用编码、企业引擎编码和 Token。如果当前工作区本身就是“氚云代码”目录,且根配置和 Token 均存在,表单会自动带出根级共享的企业引擎编码和 Token,此时只需要填写新的应用编码。一个“氚云代码”工作区只使用一个根级企业引擎编码,Token 始终可以修改;Token 如果验证过期,直接在当前页面替换新 Token 后重新提交即可。

### 增量同步(右键菜单)

1. 在资源管理器中右键点击已同步的应用文件夹
2. 选择 **"从氚云同步"**
3. 等待同步完成(Token 已自动保存到“氚云代码”目录下的 `.h3token`,enginecode 已记录在根目录 `cmax.json`,无需重复输入)
4. 如果当前应用目录存在代码变更,插件会询问是否自动提交本次 Git 变更;仅 `cmax.json` 变更时不会弹窗

**注意**: 
- 初次构建项目**只能使用命令面板**方式
- 初次构建默认使用氚云老版本接口;如需切换新版本接口,请构建完成后手动修改“氚云代码”目录下的 `cmax.json`
- 增量同步可以使用右键菜单或命令面板
- 如果“氚云代码”目录来自 GitHub clone 且缺少 `.h3token`,首次同步时插件会提示输入 Token,并自动重新生成 `.h3token`
- 使用新版工具时,旧项目需要重新执行“从氚云构建项目”生成新版目录结构和根级 `cmax.json`,不会读取旧应用目录中的配置

### 更新氚云 Token

1. 在资源管理器中右键点击“氚云代码”文件夹
2. 选择 **"更新氚云 Token"**
3. 输入一次最新的 `h3_token`
4. 插件会扫描“氚云代码”目录下的应用,并更新所有应用共用的一份 `.h3token`

也可以通过命令面板执行该命令;此时默认扫描当前工作区的第一个根目录。

## 页面与快捷键

### 从氚云构建项目页面

用于输入应用编码、企业引擎编码 `enginecode` 和 `h3_token`。

- 打开页面后,光标默认定位到“应用编码”输入框。
- `Tab`: 按“应用编码”→“enginecode”→“Token”→“应用编码”的顺序循环切换。
- `Shift+Tab`: 按相反方向在三个输入框之间循环切换。
- `Enter`: 在任意一个输入框中执行构建,等同于点击“开始构建”。
- `Esc`: 取消构建并关闭页面。

### Git 提交信息页面

用于确认或修改本次 Git 提交信息。

- 页面打开后,光标默认定位到提交信息输入框,并选中默认提交信息。
- `Enter`: 确认提交信息,等同于点击“提交变更”。
- `Esc`: 取消提交并关闭页面。

### 批量冲突处理页面

用于选择“全部使用本地版本”“全部使用远程版本”或“逐个询问”。该页面使用 VS Code 原生确认弹窗:

- `Enter`: 确认当前选中的操作。
- `Esc`: 取消并关闭弹窗。

### 单个文件差异预览页面

用于查看本地代码与氚云代码的差异,并选择使用本地版本、使用远程版本或跳过。该页面当前不额外设置 Enter/Esc 快捷键,请使用页面按钮完成操作或直接关闭页面取消。

### Token 和企业引擎编码输入弹窗

重新输入 Token 或补充企业引擎编码时使用 VS Code 原生输入框:

- `Enter`: 确认输入内容。
- `Esc`: 取消输入。

### 更新指南页面

更新指南为只读说明页面,没有需要确认或提交的操作,不设置额外快捷键。

## 智能表单验证

插件内置了智能验证机制,确保您输入的信息正确无误:

### 实时验证

当您点击"开始构建"后,插件会:
1. **验证应用编码**: 检查应用是否存在
2. **验证 enginecode**: 请求氚云接口时在 Headers 中携带企业引擎编码
3. **验证 Token**: 尝试连接氚云平台验证 Token 有效性
4. **即时反馈**: 如果有错误,会在对应字段下方显示具体错误信息

### 错误提示

- **应用编码错误**: "应用编码不存在,请检查后重试"
- **enginecode 错误**: "企业引擎编码无效,请检查后重试"
- **Token 失效**: "Token 已失效或无效,请重新获取"
- **网络错误**: 显示具体的网络连接问题

### Token 获取指南

在表单中点击 **"📖 如何获取 h3_token?"** 链接,会打开详细的图文指南,包括:
- 如何在不同浏览器中查找 Cookie
- Token 的位置和复制方法
- 常见问题解答

## Token 失效处理

如果同步时 Token 已失效,插件会:
1. 检测到认证失败(401 错误)
2. 弹出提示告知 Token 已失效
3. 提供"重新输入 Token"按钮
4. 输入新 Token 后自动继续同步
5. 新 Token 会自动保存到 `.h3token`

## 智能同步策略

插件采用智能的同步策略,确保您的代码安全:

### 字段表 (fields.md)

**策略**: 直接覆盖

- 字段表只在氚云平台中修改
- 同步时会直接用远程版本覆盖本地文件
- 无需用户确认

### 代码文件 (form-frontend.js, form-backend.cs 等)

**策略**: 差异检测 + 用户选择

同步时会:
1. **自动检测差异**: 对比本地和远程文件内容
2. **无差异**: 跳过,不做任何修改
3. **有差异**: 弹出对话框让您选择

### 冲突处理方式

当检测到代码文件有差异时,您可以选择:

#### 方式一: 批量处理(推荐)

如果有多个文件存在差异,插件会先统计数量,然后让您选择:

- **全部使用本地版本**: 保留所有本地修改,不覆盖任何文件
- **全部使用远程版本**: 用氚云平台的代码覆盖所有本地文件
- **逐个询问**: 每个文件都单独弹窗让您选择

#### 方式二: 逐个处理

对每个有差异的文件,插件会显示详细信息:
- 文件名
- 本地版本: XX 行 (XX 字节)
- 远程版本: XX 行 (XX 字节)
- 变化: +X 行, -X 行

然后您可以选择:
- **$(file-code) 使用本地版本**: 保留我的修改
- **$(cloud-download) 使用远程版本**: 覆盖为氚云版本
- **$(skip) 跳过**: 暂不处理,下次同步时再决定

### 同步流程

```
开始同步
  ↓
获取最新表单列表
  ↓
预先检测所有文件差异
  ↓
发现冲突? → 是 → 询问用户如何处理(批量/逐个)
  ↓           ↓
  否        根据用户选择处理
  ↓           ↓
直接同步    应用用户选择
  ↓           ↓
更新配置文件
  ↓
同步完成
```

### 最佳实践

1. **在氚云平台修改字段**: 同步时会自动更新 `fields.md`
2. **在本地修改代码**: 同步时会提示您选择保留哪个版本
3. **定期同步**: 建议每次在氚云平台修改后及时同步
4. **使用版本控制**: 建议将项目纳入 Git 管理,便于追踪变更

## 配置文件说明

### cmax.json

插件会自动生成此文件,记录应用和表单结构信息,用于后续增量同步:

```json
{
  "version": 2,
  "engineCode": "企业引擎编码",
  "h3yunApiVersion": "legacy",
  "systemUserId": "System用户的ObjectId",
  "apps": {
    "a1a2b3c": {
      "appCode": "应用编码",
      "appName": "应用名称",
      "lastSyncTime": "最后同步时间(ISO格式)",
      "forms": {
        "f1a2b3c": {
          "formCode": "表单编码",
          "formName": "表单名称"
        }
      }
    }
  }
}
```

字段说明:

- `version`: 根配置格式版本，当前为 `2`。
- `apps`: 以应用目录后缀为 key 的应用配置映射。
- `appCode`: `apps` 中单个应用的氚云应用编码。
- `engineCode`: 根配置级企业引擎编码,所有应用共用。
- `h3yunApiVersion`: 根配置级氚云接口版本配置,所有应用共用。
- `appName`: 应用名称。
- 应用后缀：`apps` 中的 key 即应用文件夹编码后缀,格式为 `a` 加应用编码 MD5 前缀,应用对象内不再重复保存 `appSuffix`。
- `systemUserId`: 根配置级 System 用户的 ObjectId,所有应用共用,供 MCP 工具 h3yun-sql-troubleshooter 执行 SQL 查询时使用。首次构建且根配置缺少该字段时查询并写入;后续新增应用、同步和表单名称查询均复用该值,不会重复查询。
- `lastSyncTime`: 最后同步时间。
- `forms`: 表单映射,key 为表单文件夹编码后缀,格式为 `f` 加表单编码 MD5 前缀。

### 切换氚云接口版本

如果氚云平台接口发生变化,可以在“氚云代码”目录下手动修改 `cmax.json` 根对象的 `h3yunApiVersion`:

```json
{
  "h3yunApiVersion": "new"
}
```

可选值:

- `legacy`: 使用老版本接口。新建项目默认使用此值。
- `new`: 使用新版本接口。

使用规则:

- 新建工作区时默认使用 `legacy`,不会在构建表单中让用户选择。
- 已有根级配置时,新增应用和同步均保留根级 `h3yunApiVersion` 的当前值。
- 如果发现构建或同步时接口不匹配,请先把 `cmax.json` 中的 `h3yunApiVersion` 改成 `new`,再执行“从氚云同步”。
- 同步时插件会保留该配置,不会自动改回 `legacy`。

**安全提示**: 
- Token 会以明文形式保存在 `.h3token` 中
- 插件会自动在“氚云代码”目录的 `.gitignore` 中加入 `.h3token`
- `cmax.json` 不包含 Token,但会保存根级共享的 enginecode 和 System 用户 ID,可提交到代码仓库用于记录项目结构

## 常见问题

### Q: 如何访问插件功能?

A: 
- **初次构建项目**: 只能使用命令面板
  1. 按 `Ctrl+Shift+P` 打开命令面板
  2. 输入 "从氚云构建项目" 或 "氚云"
  3. 选择对应命令

- **增量同步**: 可以使用两种方式
  1. 命令面板: 按 `Ctrl+Shift+P`,输入 "从氚云同步"
  2. 右键菜单: 在应用文件夹上右键 → "从氚云同步"

### Q: 如何获取 h3_token?

A: 
1. 在浏览器中登录氚云平台
2. 按 F12 打开开发者工具
3. 切换到 Application/存储 标签
4. 找到 Cookies 中的 h3_token
5. 复制其值

详细步骤请参考上文"首次使用:准备认证信息"章节。

### Q: 如何获取 enginecode?

A: 系统管理员可在氚云平台头像菜单进入 **系统管理** → **系统集成**,复制企业引擎编码。首次构建时必须填写,后续会保存到根级 `cmax.json`,同一“氚云代码”目录下的所有应用共用。

### Q: Token 会过期吗?

A: 是的,Token 有一定的有效期。当 Token 失效时:
- 插件会检测到认证失败
- 弹出提示让您重新输入 Token
- 输入新 Token 后会自动继续同步
- 新 Token 会自动保存到“氚云代码”目录下的 `.h3token`,下次同步无需再次输入
- 如果团队成员从 GitHub clone 项目后缺少 `.h3token`,首次同步时插件会提示输入 Token 并在“氚云代码”目录下重新生成 `.h3token`

### Q: 安装后看不到菜单项?

A: 
- **初次构建项目**: 请使用命令面板(`Ctrl+Shift+P`),输入 "从氚云构建项目"
- **增量同步**: 在“氚云代码”目录下的应用文件夹上右键可以看到 "从氚云同步" 菜单项

请确保:
- 已重启 VSCode
- 已打开一个工作区文件夹(必须打开文件夹才能使用)

### Q: 点击命令后没有反应?

A: 可能的原因:
- 网络连接问题,无法访问氚云平台 API
- 应用编码输入错误
- enginecode 输入错误或旧项目未补充 enginecode
- Token 无效或已过期
- 氚云接口响应结构发生变化,需要调整 `src/parsers` 下对应解析器
- 当前项目使用的接口版本不匹配,可尝试修改 `cmax.json` 中的 `h3yunApiVersion`

### Q: 如何切换氚云新旧接口版本?

A: 打开“氚云代码”目录下的 `cmax.json`,修改根对象的 `h3yunApiVersion` 后保存,再执行“从氚云同步”。

使用老版本接口:

```json
{
  "h3yunApiVersion": "legacy"
}
```

使用新版本接口:

```json
{
  "h3yunApiVersion": "new"
}
```

旧项目需要使用新版工具重新构建项目结构,生成包含根级 `h3yunApiVersion` 的新版 `cmax.json`。

### Q: 如何处理同名文件夹?

A: 当前插件不会使用 "应用名称-1" 这种序号方式。首次构建时会根据应用或表单编码生成稳定后缀:
- 应用文件夹格式: `应用名称(a1a2b3c)`
- 表单文件夹格式: `表单名称(f1a2b3c)`

后缀由对应编码的 MD5 前缀生成,默认哈希部分为 6 位;发生冲突时会逐步增加长度。最终后缀会记录到 `cmax.json`,后续同步按配置定位已有文件夹。已有项目继续使用配置中的旧后缀,不会自动批量重命名目录。

### Q: Token 保存安全吗?

A: 
- Token 以明文形式保存在“氚云代码”目录下的 `.h3token` 文件中
- `.h3token` 会被插件自动加入“氚云代码”目录下的 `.gitignore`,不要提交到公开仓库
- `cmax.json` 不再保存 Token,可以提交用于团队共享项目结构
- `cmax.json` 会保存 enginecode,但不会保存 Token
- 团队成员 clone 项目后,同步时输入自己的 Token 即可生成本地 `.h3token`
