氚云代码重大更新使用指南

本版本开始，多个氚云应用统一放在“氚云代码”目录中管理。

为什么会看到这个提示？
当前操作的应用可能仍然使用旧版目录结构，或者“氚云代码”目录下缺少统一的 cmax.json 或 .h3token 文件。 当前版本只从“氚云代码”目录读取根配置和 Token,应用目录下不再保存 cmax.json。
1 重新构建项目结构
  1. 在 VSCode 中打开需要保存氚云代码的工作区文件夹。
  2. 按 Ctrl+Shift+P 打开命令面板。
  3. 执行“从氚云构建项目”。
  4. 如果当前工作区就是“氚云代码”目录且已有根配置和 Token,构建表单会自动带出可复用的参数；否则输入应用编码、企业引擎编码和最新的 h3_token。
  5. 等待构建完成。工具会自动创建“氚云代码”目录，并把应用放在该目录下。
提示: 本版本不自动迁移旧项目。请重新执行一次“从氚云构建项目”，使用新方案生成项目结构。
更新后的目录结构
工作区/
└── 氚云代码/
    ├── cmax.json
    ├── .h3token
    ├── .gitignore
    └── 应用名称(a1a2b3c)/
        ├── failed-nodes(应用名称).md
        └── 表单名称(f1a2b3c)/
目录后缀说明: 应用目录后缀以 a 开头,表单目录后缀以 f 开头。默认使用对应编码 MD5 的前 6 位;如发生冲突,工具会自动增加哈希长度。
根配置说明: cmax.json 使用 version: 2 和 apps 结构,以应用目录后缀为 key 记录每个应用的编码、表单映射和同步配置。
2 以后如何同步应用
  1. 在资源管理器中展开“氚云代码”目录。
  2. 右键点击其中的应用目录，例如“应用名称(a1a2b3c)”。
  3. 选择“从氚云同步”。
  4. 工具会从“氚云代码/.h3token”读取 Token,同步当前应用目录的代码,并同时更新根配置 cmax.json；不会提交其他应用目录的代码。
3 Token 和 Git 管理变化

.h3token 统一保存在“氚云代码”目录，不再放在每个应用目录中。

cmax.json 统一保存在“氚云代码”目录,按应用后缀集中管理所有应用、表单和同步配置。

.gitignore 和 Git 仓库也统一放在“氚云代码”目录中，多个应用共用一个 Git 仓库。

注意: 请不要把 .h3token 提交到公开代码仓库。
4 多个应用如何更新 Token

右键点击“氚云代码”目录，选择“更新氚云 Token”，输入一次最新 Token 即可更新所有应用共用的 Token。

5 旧项目注意事项

本版本不自动迁移旧项目目录,也不会读取旧应用目录下的 cmax.json。如果应用仍在工作区根目录或其他旧目录中,请按照本指南重新构建一次,生成根目录配置。

重新构建完成并确认新应用可以正常同步后，再根据需要清理旧应用目录。
